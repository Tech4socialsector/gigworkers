# Gigworkers v1.0.0 – Role-based Home and Welfare Dashboards

**Release date:** 2026-11-16 · **Release type:** Major (first stable release) · **Previous version:** v0.8.0

## Summary

Version 1.0.0 is the first stable release of the Gig Workers Welfare Portal. It gives every
user, whether Welfare Board, aggregator or gig worker, a home page and a dashboard built for their
role. It also redesigns aggregator approval, restricts welfare rate changes to the Welfare Board,
and brings all portal settings onto a single page.

## Highlights

- A **role-based Home page** showing each user what needs their attention.
- New **Welfare Board**, **Aggregator** and **My Dashboard** views on one shared engine, with
  drill-down, CSV export and analytics.
- A redesigned **Aggregator Approval** page with a full application review panel.
- Only the **Welfare Board** can change welfare rates.
- All settings on one **Gig Worker Settings** page.
- Readable IDs for service categories (`SC001`) and vehicle types (`VT001`).

## Changes by module

### Role-based Home Page (new)
- `/desk/welfare-home` shows each role its own to-do list and recent activity.
- Administrators see applications to review, clarifications, overdue invoices, withdrawals to
  approve or pay, suspected duplicates, fees not yet invoiced, and the next invoice run.
- Aggregators and gig workers see their own tasks, and an activity feed that groups similar
  events from the same day.

### Admin Dashboard → Welfare Board Dashboard
- The new **Welfare Board Dashboard** replaces the Admin Dashboard.
- Filters by date, aggregator, gender, worker status, service category and district.
- Shows the headline flow of welfare money, cards for each area, and drill-down tables with
  search, sorting and **CSV export**.
- Includes a timeline for a single worker or aggregator, and an **Analytics** tab.

### Aggregator Dashboard
- Rebuilt on the shared dashboard engine. Aggregators see only their own data, and
  administrators can choose any aggregator.

### Gig Worker Dashboard
- **My Dashboard** shows a worker's own transactions, welfare fees, fund balance and
  withdrawals. Administrators can choose any worker.

### Aggregator Approval and KYC
- A redesigned review page shows the complete application, including company and KYC details,
  documents, service categories and days waiting, and supports single or bulk decisions.

### Service Management
- Only users with edit rights on Service (the Welfare Board) can change welfare rates.
  Aggregators can view rates but not change them.
- Service Categories and Vehicle Types now use readable IDs: `SC001…` and `VT001…`.

### Application Settings
- **Gig Worker Settings** now holds both the automatic approval period and the maximum number of
  transaction adjustments. It replaces *Aggregator Approval Settings* and *Gig Transaction
  Settings*.

### Web Forms and Public Registration
- The aggregator registration form shows service category **names** instead of codes.
- The aggregator registration form layout and fields have been updated.

### Reports and Analytics
- The **Welfare Fund Report** shows correct figures and an improved layout.
- Service rate history entries appear in the correct order.

## Bug fixes

- Corrected the Welfare Fund Report figures and layout.
- Fixed the order of entries in the service rate log.

## Security

- Welfare rate changes are restricted to the Welfare Board.
- The scope of every dashboard (whose data is shown) is decided on the server from the user's
  role.

## Technical changes

- New pages: `welfare-home`, `welfare-board-dashboard`. Removed page: `admin-dashboard`.
- Desk scripts are now built as bundles (`desk_overrides.bundle.js`,
  `welfare_dashboard.bundle.js`), so browsers always load the latest version.
- `webform_include_js` adds client-side support to the aggregator registration form.
- Removed DocTypes: Aggregator Approval Settings, Gig Transaction Settings.
- New patches: `merge_settings_into_gig_worker_settings`, `rename_service_category_vehicle_type_ids`.

## Breaking changes

| Change | Action required |
|---|---|
| The Admin Dashboard (`/desk/admin-dashboard`) is replaced by `/desk/welfare-board-dashboard` | Update bookmarks and links |
| *Aggregator Approval Settings* and *Gig Transaction Settings* are merged into **Gig Worker Settings** | Values are migrated automatically. Check them after upgrading |
| Service Category and Vehicle Type IDs are renamed to `SC###` / `VT###` | Links inside the portal are updated automatically. Update external systems and saved import files that use the old IDs |

## Upgrade instructions

```bash
bench --site <site> backup --with-files
cd apps/gigworkers && git fetch --tags && git checkout v1.0.0 && cd ../..
bench --site <site> migrate
bench build --app gigworkers
bench --site <site> clear-cache
bench restart
```

`migrate` runs two patches:

| Patch | What it does |
|---|---|
| `merge_settings_into_gig_worker_settings` | Copies the automatic approval period and the maximum adjustments into Gig Worker Settings, then removes the old settings |
| `rename_service_category_vehicle_type_ids` | Renames Service Categories and Vehicle Types to `SC###` / `VT###`, oldest first, and updates every link |

**Fresh installation**

```bash
bench get-app https://github.com/Tech4socialsector/gigworkers.git --branch v1.0.0
bench --site <site> install-app gigworkers
bench build --app gigworkers
bench restart
```

**After deployment**

1. Check **Gig Worker Settings** and **Gig Worker Unique ID Settings**.
2. Check that the Service Category and Vehicle Type lists show `SC…` / `VT…` IDs.
3. Sign in as an administrator, an aggregator and a gig worker. For each, check that the Home page
   and dashboard load and show only that user's data.
4. Check that `/aggregator-form` and `/gig-worker` open for visitors who are not signed in.
5. Users with the portal already open should reload the page once to get the new dashboards.
