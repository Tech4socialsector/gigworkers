# Gigworkers v0.6.0 – Partner IDs, Reports and Security Hardening

**Release date:** 2026-07-31 · **Release type:** Minor · **Previous version:** v0.5.0

## Summary

This release adds partner IDs that link gig workers to their aggregators, automatic approval of
aggregator applications, the settings for a Gig Worker Unique ID, and two new reports for the
Welfare Board. It also includes a broad security update covering accounts, one-time passwords,
payment status, sensitive fields and file uploads.

## Highlights

- **Partner IDs** and a **Worker Partner Mapping** between gig workers and aggregators.
- **Automatic approval** of aggregator applications after a set number of days.
- **Gig Worker Unique ID Settings.**
- New **Admin Summary Report** and **Welfare Fund Report**.
- An improved **Aggregator Dashboard**, with monthly trends and auto-refresh.
- A **security update** across the portal.

## Changes by module

### Gig Worker Management
- Each gig worker can carry an aggregator **Partner ID**, recorded in a new **Worker Partner
  Mapping**.
- New **Gig Worker Unique ID Settings** define how a worker's unique ID is built from ID proofs,
  a prefix and a running number.

### Aggregator Approval and KYC
- Administrators can set a number of days after which applications still in *Submitted* are
  approved automatically. A daily job applies the rule; `0` turns it off.

### Service Management
- Rate history now shows a clear **Active / Scheduled / Expired** status for each rate period.
- Fixed issues on the Service form and in the rate history.

### Gig Transactions
- The welfare rate and cap are saved on each transaction when it is recorded, so later rate
  changes do not alter past transactions.

### Aggregator Dashboard
- Updated layout, a **monthly trend** chart and **automatic refresh**.

### Reports and Analytics
- **Admin Summary Report:** workers, transactions and transaction value for each aggregator.
- **Welfare Fund Report:** fees raised, paid and outstanding, funds held, and withdrawals.

### Bulk Import and Import Logs
- The sample gig worker import template matches the current fields.
- Fixed the import log on the bulk upload page.

### User Roles and Permissions
- New **Board Secretary** role for Board Management.
- Record-level access rules now also cover Welfare Fee Payments and Welfare Benefit Withdrawals.

## Security

- New aggregator and gig worker accounts get a **random initial password**.
- One-time passwords are generated securely and stored only in hashed form, with expiry, attempt
  limits and rate limits.
- Aggregators can no longer mark their own transactions as paid. Only OTP confirmation or an
  administrator can.
- Sensitive fields (Aadhaar, PAN, their attachments, bank details, and payment status and amount
  fields) are visible only to authorised roles.
- Uploaded import files are checked for owner, file type (CSV/XLS/XLSX) and size (maximum 50 MB)
  before they are read.

## Bug fixes

- Fixed issues on the Service form and in the rate history.
- Fixed the import log on the bulk upload page.

## Technical changes

- New DocTypes: Worker Partner Mapping, Gig Worker Unique ID Settings, Aggregator Approval
  Settings.
- New reports: Admin Summary Report, Welfare Fund Report.
- New daily scheduled job for automatic aggregator approval.
- New site config key (optional): `otp_hmac_key`. If it is not set, the site's `encryption_key` is
  used.

## Breaking changes

None.

## Upgrade instructions

```bash
bench --site <site> backup --with-files
cd apps/gigworkers && git fetch --tags && git checkout v0.6.0 && cd ../..
bench --site <site> migrate
bench build --app gigworkers
bench --site <site> clear-cache
bench restart
```

There are no new patches in this release.

**Administrator actions**

1. Ask aggregator and gig worker users whose accounts were created before this release to
   **reset their passwords**.
2. Optionally, set a dedicated OTP key:
   `bench --site <site> set-config otp_hmac_key "<random value>"`.
3. Set up **Gig Worker Unique ID Settings** and the automatic approval period.
