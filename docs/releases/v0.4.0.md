# Gigworkers v0.4.0 – Bulk Import

**Release date:** 2026-05-27 · **Release type:** Minor · **Previous version:** v0.3.0

## Summary

Aggregators and administrators can now upload gig workers and gig transactions in bulk from
spreadsheets, with every upload recorded in an import log. Dashboards gain drill-down views, and
the Aggregator Dashboard has been redesigned.

## Highlights

- **Bulk Gig Worker Import** and **Bulk Gig Transaction Import** pages.
- **Import logs** recording the result of every upload.
- **Drill-down** from dashboard figures to the underlying records.
- A redesigned **Aggregator Dashboard**.

## Changes by module

### Bulk Import and Import Logs (new)
- Two desk pages for uploading gig workers and gig transactions from CSV or Excel files, with
  downloadable templates.
- Import pages are available to administrators and aggregators, with options suited to each role.
- **Gig Worker Import Log** and **Gig Transaction Import Log** keep each upload's results.
- Aggregators can use Frappe's standard **Data Import**.

### Dashboards
- Admin, Aggregator and Gig Worker dashboards support drill-down into the records behind each
  figure.
- The Aggregator Dashboard shows monthly welfare trends and a breakdown by service category.
- Suspected duplicate transactions can be handled in bulk from the Admin Dashboard.

### Gig Worker Management
- The gig worker form has updated fields.
- The **Add Gig Worker** button is hidden from the gig worker list. Workers are added through
  registration or import.

### Gig Transactions
- The *trust level* field has been removed from gig transactions.
- Payout fields are labelled more clearly ("Final payout to worker").

### Web Forms and Public Registration
- The aggregator registration form is visible again to the public.

### Notifications
- Outgoing notification emails now have an explicit sender.

## Bug fixes

- Fixed the bulk action on suspected duplicate transactions.
- Fixed several gig worker and gig transaction import errors.
- Corrected the alignment of the registration certificate.
- Fixed a migration error on Gig Transaction.

## Technical changes

- New DocTypes: Gig Worker Import Log, Gig Transaction Import Log.
- New pages: `bulk-gig-worker-import`, `bulk-gig-transaction-import`.
- Removed DocType: Worker Mapping Log.
- New patch: `add_aggregator_data_import_permission`.

## Breaking changes

| Change | Action required |
|---|---|
| The `trust_level` field is removed from Gig Transaction | Stop sending `trust_level` when creating transactions through the API |
| The Worker Mapping Log DocType is removed | None |

## Upgrade instructions

```bash
bench --site <site> backup --with-files
cd apps/gigworkers && git fetch --tags && git checkout v0.4.0 && cd ../..
bench --site <site> migrate
bench build --app gigworkers
bench --site <site> clear-cache
bench restart
```

`migrate` runs `add_aggregator_data_import_permission`. It gives the Aggregator role access to
**Data Import** and **Data Import Log**.

Bulk imports run in the background, so make sure the background workers are running.
